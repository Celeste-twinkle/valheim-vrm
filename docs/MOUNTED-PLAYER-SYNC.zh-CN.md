# 骑乘玩家在旁观者视角落到坐骑脚下

游戏的 `ZSyncTransform.OwnerSync` 原本只在父对象 ZDO 改变时更新挂点名。
玩家先站在坐骑身上、再骑上同一只坐骑时，父对象没有改变，但挂点应当
从空字符串变成鞍座挂点。`Player.GetRelativePosition` 在骑乘时同时把相对
位置设为零；漏发挂点后，旁观者就把玩家放到坐骑原点。骑乘者通过本地
`UpdateAttach` 跟随鞍座，所以自己看到的位置仍然正常。

`src/PlayerAttachmentSync.cs` 补充两条客户端修复路径：

- 拥有玩家 ZDO 的客户端，在原生同步之后单独比较并同步挂点名。下马后
  即使仍站在同一只坐骑上，也会清空鞍座挂点；状态不变时不重复写网络数据。
- 旁观者收到旧客户端漏发的空挂点时，只在父对象确为该玩家正在使用的
  鞍座、原生 Animator 的同步骑乘标记为真、鞍座有效且激活时恢复位置。
  修复发生在原生方法更新坐骑和朝向之后，不改接收到的 ZDO 数据。

骑乘者更新客户端后，原版接收逻辑也能获得正确挂点；旁观者更新客户端
则能恢复上述旧发送端情况。服务器插件和网络格式无需修改。

2026-10-04 使用公开版 2.0.5 的同一份 DLL，在隔离的 Valheim 1.0.16 和
1.0.12 / Unity 6000.0.75 游戏运行时分别验证：

- 反向补丁执行未修改的游戏方法，复现“站在坐骑上 → 骑乘同一父对象”
  漏发挂点；测试鞍座距坐骑原点约 3.13 米，远端玩家确实落到原点。
- 验证修复发送端与未修改接收端、旧发送端与修复旁观者两条路径。
- 60 次同一父对象上下坐骑，变化朝向、平移和 20/1200 米海拔，无位置漂移。
- 100 次相同状态同步不增加 `DataRevision`；站立、其他骑手、未激活或
  未加载的鞍座、坐骑后加载、非拥有者调用和彻底脱离均通过。
- VRM 0.x 与 VRM 1.0 模型在 1.4/2.0/2.2 米身高下，每个游戏版本
  共 540 次移动转向采样；独立烘焙网格的座面偏差最大约 0.93 毫米，保留
  坐姿和模型高度偏移。
- 客户端和测试项目编译均为零警告、零错误；最终引擎运行日志无异常。

验证见 [2.0.5 验证记录](release-2.0.5-validation.md)。本次本地结果位于
