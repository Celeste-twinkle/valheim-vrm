# 配置保存修复与诊断（2.0.4）

针对模型切换成功却提示 `Avatar switch failed: 无法删除要被替换的文件` 的反馈，2.0.4 正式版统一改进模型选择、高度、站姿／坐姿偏移 TXT、动作／装备校准、部件、物理和渲染选项的保存逻辑。

## 安装和复现

1. 退出游戏，备份现有 `BepInEx/plugins/ValheimVRM/ValheimVRM.dll`。
2. 将更新包里的 `BepInEx` 文件夹合并到游戏目录，替换上述 DLL。
3. 启动后，在 `BepInEx/LogOutput.log` 确认加载 `ValheimVRM 2.0.4`。
4. 进入世界，连续切换两次模型，检查 `BepInEx/config/ValheimVRM/avatar_selections.json` 是否记录最后一次选择。
5. 需要检查 TXT 时，在 F8 调整“站姿高度偏移”或“坐姿高度偏移”，松开滑块并关闭菜单，再检查 `settings_模型名.txt`。
6. 退出游戏后保留完整 `BepInEx/LogOutput.log`。下一次启动可能覆盖日志，应先复制一份。

普通模型切换不会自动创建 TXT；没有可选 TXT 时使用默认参数。身高滑块保存的是 `avatar_heights.json`，站姿／坐姿高度偏移保存的才是 TXT。`global_settings.txt` 仍由用户按需手动创建。

## 文件与记录对应关系

以下文件均位于 `BepInEx/config/ValheimVRM/`。JSON 文件数量少于模型数量是正常现象；共用一个容器文件不表示所有模型共用同一条记录。

| 文件 | 如何区分设置 |
| --- | --- |
| `avatar_calibration.json` | 按模型名记录动作／装备校准；不同模型独立。 |
| `avatar_parts.json` | 按模型名记录部件显示／隐藏；不同模型独立。 |
| `avatar_selections.json` | 按游戏角色名记录当前选择的模型或原始角色。 |
| `avatar_heights.json` | 按游戏角色名记录模型身高。 |
| `settings_模型名.txt` | 每个模型单独一个可选 TXT；保存站姿／坐姿偏移会生成／更新。 |
| `rendering_options.json` | 当前客户端通用的场景光照、接收阴影和泛光选项。 |
| `physics_options.json` | 当前客户端通用的物理摆动权重偏好。 |
| `global_settings.txt` | 可选全局参数，由用户按需手动创建。 |

## 保存行为

- 每次保存使用同目录的独立临时文件，避免旧 `.tmp` 或其他保存操作冲突。
- 更新已有配置时使用带恢复副本的 `File.Replace`。短暂占用及替换错误最多尝试三次，总等待不超过 60 ms。
- 在 Windows 上，错误 1175／1176／1177、替换不支持等情况可转用 `MoveFileExW`。这一步先保留恢复副本，再替换文件；不会先删除或直接截断原配置。
- 部分替换失败使目标缺失时，尝试用恢复副本还原旧配置。恢复也失败时，保留副本并记录位置。
- 只读文件和真实的访问权限／持续占用问题继续明确报错，不自动修改原文件属性或权限。
- 清理临时文件或成功保存后的副本失败时，单独记日志，不覆盖原异常，也不把已保存的操作报告成失败。
- 外观应用成功但选择保存失败时，菜单提示“模型已切换，但选择记录保存失败；本次游戏内仍保留此选择”。本次游戏内的复活继续使用新选择；重新启动仍依赖上次真正保存的记录。切回原始角色同样可以在保存不可用时生效。

## 日志字段

配置诊断行统一以 `[ValheimVRM Config]` 开头，不输出配置内容。

| 标记 | 含义 |
| --- | --- |
| `CONFIG_DIRECTORY` | 实际配置路径、目录属性、文件系统、剩余空间、系统及运行时版本。 |
| `MODEL_SETTINGS_READ` / `MODEL_SETTINGS_DEFAULT` | 读取哪个模型 TXT，或因缺少可选 TXT 而使用默认参数。 |
| `SAVE_START` | 本次保存的目标、临时文件、恢复副本路径及原文件属性。 |
| `REPLACE_FAILED` | 替换尝试次数、异常类型、HRESULT、可解析的 Windows 错误码。 |
| `SAVE_FALLBACK` | 开始使用 Windows 替换后备方式及恢复副本路径。 |
| `SAVE_OK` | 最终保存成功及实际使用的方法。 |
| `SAVE_FAILED` | 失败阶段、完整路径、目标／临时／副本／目录属性、文件系统、剩余空间、异常码和完整堆栈。 |
| `SAVE_RESTORED` / `RESTORE_FAILED` | 部分替换失败后的还原结果；还原失败会给出可用副本的位置。 |
| `CLEANUP_FAILED` | 清理失败文件的路径和异常码。 |

阶段可区分 `create-directory`、`write-temporary`、`move-new`、`replace`、`fallback-backup` 和 `fallback-move`。例如 `win32=32` 表示共享冲突，`win32=5` 表示拒绝访问，`win32=1175` 对应无法删除被替换文件。若运行时没有提供 Windows HRESULT，记录 `win32=unknown`，同时保留原始消息和堆栈。

日志能说明失败步骤和文件状态，不能自动识别持有文件的另一个进程。发生持续错误时，结合该文件的属性、安全权限及文件占用情况检查。文件夹“只读”勾选本身不能证明缺少写入／删除权限。

## 验证

保存回归覆盖连续更新、短暂占用重试、注入 Windows 1175、替换不支持、部分替换后的后备保存／还原、只读和占用时保留旧文件、目录创建失败、清理不覆盖原异常、日志异常不影响保存，以及保存失败后的当前会话／原始角色选择。

回归同时在 .NET 7 和游戏自带的 Unity Mono 中执行。游戏内探针已加入 `AvatarSyncEngineTests`，可验证真实模型／原始角色切换、错误提示和 TXT 创建／保留其他参数；完整场景验证需要测试时没有正在运行的游戏进程。
